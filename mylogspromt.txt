8) README.md (answer the 5 questions explicitly + runbook)

Include clear sections:

Q0. How are dependencies managed so nothing breaks?
	•	We use a dedicated venv (.venv) + pinned versions in requirements.txt.
	•	Nothing is installed globally.
	•	Hugging Face caches inside ./models/hf to avoid polluting user’s home.

Q1. How does it get the base model?
	•	Uses Ollama with llama3:instruct. Install once, then pull the model:

# Install Ollama (see https://ollama.com/download)
ollama serve &            # ensure it’s running
ollama pull llama3:instruct


	•	The app auto-detects Ollama. If not found, it falls back to a rule-based summary.

Q2. How is data vectorized?
	•	We convert each Excel row to a readable text string and create embeddings with
sentence-transformers/all-MiniLM-L6-v2.
	•	Embeddings are normalized and stored in FAISS.

Q3. What vector database is used?
	•	FAISS (CPU) stored locally under ./index/ (faiss.index + meta.jsonl).
	•	To rebuild the index:

source .venv/bin/activate   # or .\.venv\Scripts\Activate.ps1
python ingest.py



Q4. How is it integrated with Gradio?
	•	We use Gradio ChatInterface in app.py.
	•	It keeps session history, streams LLM answers (when Ollama is available), and shows citations.

Runbook

# 1) Create venv and install deps
bash setup_env.sh             # or .\setup_env.ps1 on Windows

# 2) (Optional but recommended) run Ollama locally and pull the model
ollama serve &
ollama pull llama3:instruct

# 3) Put the 3 Excel files into ./data/
#    20230118-20240418-MovedLoads.xlsx
#    BI-Regions.xlsx
#    UserEmails.xlsx

# 4) Build the FAISS index
source .venv/bin/activate
python ingest.py

# 5) Launch the chatbot
python app.py
# Open http://localhost:7860
